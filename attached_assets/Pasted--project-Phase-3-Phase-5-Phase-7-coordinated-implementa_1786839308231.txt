मेरे मुख्य requirements:

1. MINI APP → LIVE MICROPHONE → TELEGRAM VOICE CHAT

Telegram Mini App के अंदर से मेरे phone का real microphone इस्तेमाल होना चाहिए।

Flow:

Telegram Mini App
→ microphone permission
→ real-time low-latency audio capture
→ WebSocket
→ Python backend
→ authenticated user's existing UserbotClient
→ existing VoiceChatManager
→ PyTgCalls
→ Telegram Voice Chat

Existing `.vcjoin` से मेरा hosted userbot VC में join करता है। उसी existing session और VoiceChatManager को reuse करो।

अगर user VC में connected नहीं है तो Mini App में साफ error दिखाओ।

Browser में Telegram session string, API hash, bot token या कोई secret कभी expose मत करो।

2. LIVE MIC CONTROLS

Mini App में ये controls बनाओ:

- Start Live
- Stop Live
- Mic ON/OFF
- Push-To-Talk
- Live connection status
- VC connection status
- Volume/Gain control

Mic बंद होने पर audio Telegram VC में नहीं जाना चाहिए।

Browser disconnect होने पर audio pipeline और server-side resources safely cleanup होने चाहिए।

WebSocket reconnect सुरक्षित तरीके से implement करो, लेकिन duplicate audio streams नहीं बनने चाहिए।

3. LIVE VOLUME / GAIN

मेरे existing `.volume` command को break मत करो।

Live microphone के लिए वही concept इस्तेमाल करो:

100 = 1x
200 = 2x
500 = 5x
1000 = 10x
2000 = 20x
आदि।

जितनी value user देता है, उसी के अनुसार live microphone gain बढ़े।

Artificially 100 या 200 जैसी छोटी maximum limit मत लगाओ।

Library/PCM/FFmpeg की वास्तविक numeric limitation का सम्मान करो और overflow/clipping को technically handle करो।

Noise reduction मत लगाओ।
AI voice enhancement मत लगाओ।
Voice changer मत लगाओ।
Pitch change मत लगाओ।

केवल आवश्यक resampling/channel conversion और gain processing करो।

4. EXISTING `.play` COMPATIBILITY

पहले verify करो कि current PyTgCalls version में `.play` और live microphone को simultaneously safely mix किया जा सकता है या नहीं।

अगर proper audio mixer बनाना जरूरी है तो existing playback को break किए बिना mixer architecture implement करो।

अगर current installed PyTgCalls APIs में simultaneous mixing safely possible नहीं है, तो पहले version में live mic शुरू करते समय active playback को रोकने/रोकने की स्पष्ट सूचना देने वाला safe behavior रखो।

Existing `.play`, `.pause`, `.resume`, `.vcstop`, `.vcleave`, `.volume` और queue behavior को break मत करो।

Telegram Voice Chat
→ PyTgCalls incoming StreamFrames
→ frame format detection/decoding
→ browser-compatible audio
→ WebSocket
→ Mini App
→ phone speaker/headphones

पहले installed PyTgCalls 2.3.3 और ntgcalls 2.2.5 की वास्तविक APIs और StreamFrames payload format verify करो।

अगर incoming audio payload reliably decode/convert किया जा सकता है, तो actual two-way audio implement करो।

अगर current library में यह officially/technically possible नहीं है, तो fake audio मत बनाओ। Exact limitation document करो और UI में साफ status/error दिखाओ।
